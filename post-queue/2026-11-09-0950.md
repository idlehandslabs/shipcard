# Reply bank #2: agents and keys (2026-11-09)

Three more reply-sized answers. No links, no pitch. Each under 270 characters.
Yesterday's bank covered .env, deleted keys and bot keypairs; these are new questions.

## 1. "My .env is in .gitignore, so I'm fine, right?"
.gitignore only stops git add from picking the file up. It does nothing if the file was committed before, or if an agent copies the key into a config, a test or a log. Check what actually leaves: scan the diff before every push.

## 2. "Is it OK to paste my private key into a chat to debug a signing error?"
No. Debug with a throwaway keypair holding zero funds; signing bugs reproduce the same with any key. If the real one already went into a chat, treat it as exposed: move the funds first, then swap the key in your config.

## 3. "My agent asked to read ~/.config/solana/id.json. Allow it?"
Ask why. Reading it is how a key ends up quoted in a log or a commit. Most tasks only need the public address: give it that. If it must sign, point it at a devnet keypair made for the agent, never your main wallet.
